# ADR 0002 — 수집 데이터는 git 에 두고, 전달만 분할한다

- 상태: 채택
- 날짜: 2026-08-29

## 배경

매일 밤 뉴스를 수집해 쌓는 파이프라인이 있다. "누적되는 데이터가 있으니 DB 가
필요한 것 아닌가" 라는 질문이 자연스럽게 나왔다.

측정부터 했다.

```
src/data/signals/            뉴스 신호 290건 (365일 상한 1500건)
src/data/relationship-sources.json   근거 링크 162건
src/data/relationships.ts     관계 266개
src/data/politicians/         인물 101명
                              합계 약 650KB
```

DB 가 해결하는 문제들을 하나씩 대보면:

| DB 가 주는 것 | 이 프로젝트 |
| --- | --- |
| 동시 쓰기 | 쓰는 주체가 야간 배치 하나뿐 |
| 질의·인덱스 | 런타임 질의 없음. 작은 집합을 메모리에서 필터 |
| 대용량 | 365일 상한으로 설계상 유계 |
| 버전·복구 | git 커밋이 곧 스냅샷 |
| 사용자별 상태 | 없음 |

버전 관리는 오히려 git 이 낫다. 실제로 야간 실행이 아카이브를 239건 → 4건으로
잘랐을 때 git 이력에서 복구했다. DB 였다면 백업 정책을 따로 세워야 했을 일이다.

**진짜 문제는 저장이 아니라 전달이었다.** `news-signals.json` 을 정적 import 하고
있어 아카이브 전체가 메인 번들에 들어갔다. 방문자는 화면에서 신호 몇 개만 보는데
290건을 전부 받았고, 상한까지 차면 1.5MB 가 될 예정이었다.

## 결정

DB 를 넣지 않는다. 대신 전달을 셋으로 나눈다.

```
src/data/signals/index.json     매니페스트 — 월 목록·집계·인물별 건수 (1KB, 즉시)
src/data/signals/recent.json    첫 화면이 쓰는 몫 (인물당 4 + 전체 6, 즉시)
src/data/signals/YYYY-MM.json   월별 전체 아카이브 (시계열 열 때만)
```

핵심은 `recent.json` 의 크기가 **아카이브가 아니라 인물 수에 비례**한다는 점이다.
아카이브가 1년치로 차도 이 파일은 그대로다. `core.test.mts` 가 이 성질을 고정한다 —
입력을 10배로 늘려도 `pickRecent` 결과 크기가 같아야 통과한다.

인물별 건수는 매니페스트에서 읽는다. 즉시로드분이 4건이어도 화면에는 "17건" 이
정확히 뜬다.

월 파일은 이름이 달마다 바뀌어 정적 import 가 불가능하므로 `import.meta.glob` 으로
지연 import 맵을 만든다.

**예외 하나.** 방문자 카운터에는 Vercel KV 를 쓴다. 여러 사용자가 동시에 값을 바꾸고
그 값이 서버에 남아야 하므로 정적 파일로는 불가능하다. 이것이 이 저장소에서 DB 가
정당한 유일한 지점이다. KV 는 읽기/쓰기 명령 하나짜리라 스키마도 마이그레이션도
커넥션 풀도 없고, 미설정 시 컴포넌트가 스스로 숨어 앱이 멀쩡하다.

## 결과

- 메인 번들 842KB → 749KB (gzip 324 → 280KB)
- 월 파티션이 별도 청크로 분리 (2026-07 31KB · 2026-08 204KB)
- E2E 가 양방향으로 확인한다: ANALYSIS 진입 전 0청크 · 진입 후 2청크
- 아카이브가 커져도 초기 로딩량이 늘지 않는다

## 언제 이 결정을 뒤집는가

아래 중 하나라도 생기면 DB 를 다시 검토한다.

- 사용자 계정·저장된 관찰목록·제보 접수 등 **사용자별 상태**가 생길 때
- 아카이브가 **50MB 이상**으로 커질 때 (현재 0.65MB, 상한 도달 시 1.5MB)
- 클라이언트가 감당 못 하는 질의가 필요할 때
  (예: "2024년 이후 초당적 관계가 깨진 페어 상위 20")
- 쓰는 주체가 둘 이상이 될 때

브라우저에서 SQLite/DuckDB 를 WASM 으로 돌리고 CDN 의 파일을 HTTP range 로 읽는
방법도 있지만, 런타임만 1~2MB 라 데이터가 650KB 인 지금은 순손실이다. 데이터가
50배쯤 됐을 때 의미가 생긴다.
