# 로드맵 — 영향력 지도로 확장

> 2026-08-29 작성 후 두 차례 비판적 점검을 거쳐 수치와 판단을 정정했다.
> 무엇이 틀렸었는지는 맨 아래 "정정 이력" 에 남긴다.

## 어디서 나온 요구인가

Reddit 공유 후 받은 제안이다.

> 스태퍼들 간의 관계, 그리고 그들이 어느 정치인·정무직·관료·로비 단체에서
> 일했는지, 여기에 어떤 기부자가 어느 후보에게 돈을 냈는지(기부금 데이터,
> LDA 로비 신고, 스태퍼 명단, 의회·위원회 표결 기록)까지 한곳에 모아 놓으면
> 미국의 정책·입법 결정에 **누가 또는 무엇이 영향을 주는지** 더 큰 그림이
> 보일 것이다. 다만 데이터를 통합하는 일이 만만치 않다는 것도 안다.

마지막 문장이 정확하다. 그래서 각 소스가 실제로 접근 가능한지와 현재 데이터셋에
얼마나 붙는지를 재서 기록한다.

## 통합의 관건은 수집이 아니라 조인이다

소스마다 같은 사람을 다른 id 로 부른다. Voteview 는 `icpsr`, FEC 는 `fec`,
OpenSecrets 는 자체 id 를 쓴다. `congress-legislators` 가 한 레코드에 이것들을
함께 들고 있다:

```
bioguide · thomas · lis · govtrack · opensecrets · votesmart · fec
cspan · wikipedia · house_history · ballotpedia · maplight · icpsr · wikidata
```

**이것이 실질적 진입점이다.** 단, `legislators-current.json` 만 쓰면 안 된다 —
역대 파일(`legislators-historical.json`)까지 합쳐야 전직 의원이 잡힌다.

## 커버리지 (현직 + 역대 기준)

1단계를 끝냈다. 아래는 **파일에 박힌 확정값**이다 (`src/data/crosswalk.json`).

```
101명 중 매칭            84 (83%)
  icpsr 보유 (표결)      84
  fec 보유 (기부금)      83

미매칭 17 — 트럼프·머스크·주지사 등 연방의회 경력이 없는 인물
```

전에 75~79 로 흔들렸던 것은 이름 매칭이 휴리스틱이었기 때문이다. 확정한 뒤 84 다.
숫자가 커진 이유는 알고리즘을 느슨하게 해서가 아니라, **자동이 포기한 15명을 사람이
하나씩 확인해 적었기** 때문이다. 판단과 근거는 `crosswalk-overrides.json` 에 남아 있다.

여전히 **전원에게 붙지는 않는다.** 트럼프·머스크·주지사 일부는 표결도 후보
기록도 없다. "기부금 데이터 추가" 라고만 쓰면 나머지를 보는 사람은 데이터 없음을
결함으로 읽는다.

그리고 엣지 기준으로 보면 범위가 더 좁다:

```
266개 엣지 중 양쪽 다 의원  145 (55%)
```

이전에 28% 로 적었던 것은 현직만 보고 센 결과였다. 확정 후에는 55% 이고,
그 145개는 양쪽 다 icpsr 를 가지고 있어 표결 대조가 가능하다.

## 데이터가 실제로 무엇을 말하는지 — 오독하기 쉬운 지점들

### 기부금은 "누가 누구에게 줬는가" 로 끝나지 않는다

FEC 공시에는 구조적 사각이 있다.

- 개인 기부는 **200달러 초과분만** 항목화된다. 소액은 총액으로만 남는다
- Super PAC 의 독립 지출은 후보와 **조율이 금지**돼 있어 "후보에게 준 돈" 이 아니다.
  그런데 액수는 직접 기부보다 훨씬 크다
- 501(c)(4) 등의 자금은 **기부자를 공시하지 않는다**

즉 FEC 만으로 "영향력" 을 그리면 **가장 영향력 있는 돈이 빠진 그림**이 나온다.
직접 기부만 표시하고 그것을 영향력으로 읽게 두면 오히려 오도한다. 이 레이어를
만들 거라면 "공시된 직접 기부에 한한다" 를 화면에 명시해야 한다.

### LDA 는 "누가 누구를 로비했는가" 를 말해주지 않는다

로비 신고서는 **로비 회사 → 고객 → 이슈 영역 → 접촉한 기관/원(院)** 을 담는다.
특정 의원 이름과 연결되는 경우는 드물다. 그래서 "로비스트 → 정치인" 엣지는
LDA 에서 직접 나오지 않는다. 만들 수 있는 것은 **고객 ↔ 이슈 ↔ 기관** 수준의
연결이고, 그것도 유용하지만 요구된 것과는 다르다.

### 스태퍼 — "공개 소스가 없다" 는 틀렸다

하원이 **직접 공개한다.** Statement of Disbursements 는 분기마다 전체 지출을 CSV 로
내는데, 그 안에 인건비 상세가 있다. 실제로 받아서 확인했다.

```
2026 2분기 파일   26 MB · 133,091 행
  인건비 상세      22,452 행
  스태퍼 실명      14,268 명   (VENDOR NAME)
  사무실           553 개      (ORGANIZATION — "HON. 아무개")
  직위             DESCRIPTION ("SENIOR POLICY ADVISOR" 등)
아카이브          2016년부터 분기별 — 약 40개 분기
```

이름·소속·직위·급여가 **정부가 스스로 낸 공식 기록**이다. 상용 DB 를 베끼는 것과
다르다. 다만 앞서 적은 "연락처는 다루지 않는다" 는 그대로 유효하다 — 명부와
연락처는 다른 것이고, SOD 에 연락처는 없다.

**그런데 이 그래프에는 거의 안 붙는다.** 두 분기(2024 Q2 / 2026 Q2)를 실제로 비교했다.

```
양쪽 분기에 모두 있는 스태퍼      6,951
실제로 사무실을 옮긴 사람         1,198
의원 → 의원 이동 경로            775 (스태퍼 875명분)
  그중 양쪽 다 POLARIS 인물       4 개  ·  전부 n=1
POLARIS 101명 중 하원 사무실 보유  20 명 (나머지는 상원·행정부·주지사)
```

n=1 짜리 4개는 신호가 아니라 잡음이다. 게다가 **상위 이동 경로는 대부분 동맹이 아니라
승계다** — Connolly → Walkinshaw(사망 후 보궐 승계), Grijalva → Grijalva(부녀),
Lamborn → Crank(같은 지역구 후임). 이걸 그대로 엣지로 만들면 "의석이 넘어간 것" 을
"정치적 동맹" 으로 표시하게 된다.

그리고 상원 SOD 는 senate.gov 에 있어 이 망에서 막힌다. POLARIS 인물의 다수가
상원(38명)이므로, 하원 자료만으로는 애초에 반쪽이다.

**결론: 스태퍼 데이터는 지금 명단을 유지한 채 얹을 레이어가 아니다.**
535명 전원으로 명단을 넓히기로 결정할 때 비로소 값이 생긴다. 순서가 반대였다.

### 공동발의 — 표결보다 이쪽이 낫다

GovInfo 가 법안 현황을 벌크 zip 으로 낸다. 상원 119대 = 12.6MB, 5,367건.
각 법안에 발의자와 공동발의자가 `bioguideId` 와 날짜까지 붙어 들어있다.

```
상원 119대에서 추출한 공동발의 쌍     4,331
  양쪽 다 POLARIS 인물               518
기존 엣지 중 공동발의로 뒷받침되는 것  21 / 120
```

**표결 일치도보다 공동발의가 나은 이유:** 표결은 당론에 끌려간다. Cruz × Hawley 가
98.6% 일치하는 것은 관계가 아니라 소속이다. 반면 남의 법안에 이름을 올리는 것은
개인의 선택이고, 날짜가 남고, 출처가 `congress.gov` 로 특정된다.

당장 눈에 띄는 공백이 있다. **Markey × Warren 은 78건을 함께 발의했는데 우리
그래프에 엣지가 없다.** 매사추세츠 두 상원의원이다. 반대로 Padilla × Schiff(68건)는
이미 있다. 큐레이션이 놓친 곳을 이 데이터가 지목해 준다.

## ADR 0002 는 아직 유지될 수 있다

처음에는 "FEC 는 수백만 건이라 DB 재검토가 필요하다" 고 적었으나 과장이었다.
**후보 집계 벌크 파일은 193KB** 다. 개별 기부 명세(itemized)가 거대한 것이고,
이 프로젝트가 필요한 것은 후보·위원회 단위 집계다.

즉 집계만 저장하면 ADR 0002("git 에 두고 DB 안 쓴다")를 지킬 수 있다.
명세까지 다루기로 결정하면 그때 재검토한다.

## 단계

작은 것부터, 각 단계가 그 자체로 값이 있게.

**1단계 — 조인 기반  ·  완료**
`npm run crosswalk`. 현직 의원 537명 전원 + 우리가 참조하는 전직 22명에게
`bioguide`·`icpsr`·`fec`·`govtrack`·`opensecrets` 를 묶어 `src/data/crosswalk.json` 에 넣는다.
101명은 그 위에 얹는다. 화면은 안 바뀌지만 이후 전부가 여기에 얹힌다.

두 가지가 이 단계에서 드러났다.

**icpsr 는 congress-legislators 만으로는 절반뿐이다.** 현직 537명 중 319명만
가지고 있었다. 그대로 2단계에 갔으면 표결 대조가 **41% 조용히 빠진 채** 돌았을
것이다. Voteview 원본 명부(`HSall_members.csv`)에서 bioguide 로 조인해 채웠고,
지금은 559/559 다.

**"후보 없음" 을 자동 확정으로 처리하면 샌다.** Mike Lawler·Dick Durbin·Chris Murphy
등 7명이 그렇게 빠져 있었다 — 원본은 Michael·Richard·Christopher 이고 별칭 필드가
비어 있다. 통칭 사전을 만드는 대신, 성이 같은데 못 맞춘 경우를 사람에게 올리도록
바꿨다. 15명을 확인해 `crosswalk-overrides.json` 에 적었고, 적지 않으면 스크립트가
쓰지 않고 종료 코드 1 로 끝난다.

**2단계 — 공동발의 엣지  ·  완료**
`npm run cosponsor`. GovInfo BILLSTATUS 벌크(119대 법안 15,544건)에서 발의자 ↔
공동발의자 쌍 48,714개를 뽑고, 10건 이상인 125쌍을 엣지로 만든다. 이미 큐레이션된
13쌍은 제외해 실제로 늘어나는 것은 112개다.

**표결이 아니라 공동발의를 쓴다.** 표결은 당론에 끌려간다 — Cruz × Hawley 98.6% 는
"동맹" 이 아니라 "둘 다 공화당" 이다. 남의 법안에 이름을 올리는 것은 개인의 선택이고,
날짜가 남고, 출처가 congress.gov 로 특정된다.

**그래도 원시 건수는 여전히 소속을 다시 쓴다.** 10건 이상 쌍의 84% 가 같은 당이고,
상위권은 법안을 많이 내는 사람들이 차지한다. 그래서 기준선을 둔다. 5건으로 내리면
신규 264개가 되어 큐레이션한 266개가 묻힌다.

초당적 19쌍이 가장 새로운 정보다 — Fitzpatrick × Gluesenkamp Perez 19건,
Collins × Klobuchar 15건, Lawler × Torres 12건, Cruz × Warnock 9건. 전부 신규다.

**측정값과 편집 판단을 같은 선으로 그리지 않는다.** `cosponsor` 는 별도 타입이고
범례에서 따로 끈다. 기존 엣지 145개 중 공동발의로 뒷받침되는 것은 41개뿐인데,
이것은 우리 엣지가 틀려서가 아니라 큐레이션한 것 대부분이 반목·후원·갈등이라
애초에 공동발의가 나올 관계가 아니기 때문이다. 두 층이 다른 것을 말한다.

표결(Voteview)은 남겨 둔다. icpsr 는 559/559 로 갖춰져 있으니 필요해지면 바로 쓴다.

**3단계 — 기부 흐름 (별도 레이어, 방향 있음)**
OpenFEC 집계로 후보별 주요 자금 출처를 얹는다. 기존 관계 그래프와 섞지 않고
토글로 전환한다. 화면에 **"공시된 직접 기부에 한한다"** 를 명시한다.

**4단계 — 로비 (기관 수준)**
senate.gov 접근을 다른 망에서 먼저 확인한다. 만들 수 있는 것은 고객↔이슈↔기관
연결이지 로비스트↔의원 엣지가 아니라는 것을 전제로 설계한다.

**5단계 — 회전문 (명단 확대를 결정한 뒤에만)**
하원 SOD 로 스태퍼 이동을 그린다. 단, 현재 101명 기준으로는 유효 엣지가 4개(n=1)뿐이라
**지금 하면 안 된다.** 535명 전원으로 넓히기로 한 뒤에 값이 생긴다.
승계(보궐·후임·친족)를 동맹과 구분하는 규칙이 선행 조건이다. 연락처는 다루지 않는다.

## 착수 전 결정할 것

- 측정값(표결·기부)과 편집적 판단(266개 엣지)을 **화면에서 어떻게 구분**할 것인가
- 의회 경력이 없는 26명을 어떻게 다룰 것인가 (빈 값 / 별도 뷰 / 범위 축소)
- 소스가 늘면 야간 작업의 실패 지점도 는다. 이번 세션만 해도 야간 파이프라인이
  세 번 깨졌다(누적 소실·git add 경로·수집 시각). 감사 게이트를 소스마다 붙일 것인가

이 셋에 답이 없으면 1단계까지만 하고 멈추는 것이 낫다.

## 확인하면서 밟은 함정

**HTTP 200 이 접근 가능을 뜻하지 않는다.** `disbursements.house.gov` 는 존재하지 않는
경로에도 200 과 HTML 을 돌려준다. 처음 점검에서 "SOD 접근 가능" 으로 기록했지만 받은
것은 랜딩 페이지였다. Content-Type 과 실제 바이트를 봐야 한다. 근거 링크 생존 검사에서
news.google.com 이 자기 페이지로 200 을 주던 것과 같은 함정이다 — **두 번째다.**

**파일명은 규칙이 없다.** SOD 아카이브는 `APR-JUN 2017 DETAIL GRID.csv`,
`APR-JUNE-2018-SOD-DETAIL-GRID.csv`, `APRIL-JUNE 2026 SOD DETAIL GRID-FINAL.csv` 가
섞여 있다. URL 을 조립하면 안 되고 아카이브 페이지에서 링크를 긁어야 한다.

**같은 사무실이 다른 이름으로 나온다.** 첫 계산에서 이동자가 2,504명으로 나왔는데,
`FISCAL YEAR 2024 CHIEF ADMIN OFCR` → `FISCAL YEAR 2026 CHIEF ADMIN OFCR` 를 이동으로
센 것이었다. 연도 라벨을 지우니 1,198명이었다. **절반이 거짓이었다.**
