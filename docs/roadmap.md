# 로드맵 — 영향력 지도로 확장

## 어디서 나온 요구인가

Reddit 공유 후 받은 제안이다(2026-08-29).

> 스태퍼들 간의 관계, 그리고 그들이 어느 정치인·정무직·관료·로비 단체에서
> 일했는지, 여기에 어떤 기부자가 어느 후보에게 돈을 냈는지(기부금 데이터,
> LDA 로비 신고, 스태퍼 명단, 의회·위원회 표결 기록)까지 한곳에 모아 놓으면
> 미국의 정책·입법 결정에 **누가 또는 무엇이 영향을 주는지** 더 큰 그림이
> 보일 것이다. 다만 데이터를 통합하는 일이 만만치 않다는 것도 안다.

마지막 문장이 정확하다. 그래서 "하면 좋겠다" 로 남기지 않고, 각 소스가 실제로
접근 가능한지와 현재 데이터셋에 얼마나 붙는지를 재서 기록한다.

## 통합의 관건은 수집이 아니라 조인이다

각 소스를 받아오는 것은 어렵지 않다. 문제는 **같은 사람을 소스마다 다른 id 로
부른다**는 것이다. Voteview 는 `icpsr`, FEC 는 `fec`, OpenSecrets 는 자체 id 를 쓴다.

`congress-legislators` 가 이 조인을 해결한다. 한 레코드가 다음을 함께 들고 있다:

```
bioguide · thomas · lis · govtrack · opensecrets · votesmart · fec
cspan · wikipedia · house_history · ballotpedia · maplight · icpsr · wikidata
```

즉 이 파일을 조인 테이블로 쓰면 표결·기부금·로비를 한 인물로 묶을 수 있다.
**이것이 이 확장의 실질적 진입점이다.**

## 커버리지 현실

현재 101명 중 얼마나 붙는지 실측했다.

```
현직 의원으로 매칭        56명 (55%)
  그중 icpsr + fec 둘 다   39명 (39%)

미매칭 45명
  전직/레거시 19 · 행정부 8 · 주지사 8 · 상원 6 · 하원 2 · 비선출 2
```

**절반 조금 넘는다.** 트럼프·머스크·주지사·각료·전직 의원은 표결도 FEC 후보
기록도 없거나 다르다. 이 확장은 그래프 전체가 아니라 **의회 부분에만** 붙는다.

이것을 숨기면 안 된다. "기부금 데이터 추가" 라고 써 놓고 39%에만 적용되면
나머지 61%를 보는 사람은 데이터가 없는 것을 결함으로 읽는다.

## 이 확장이 프로젝트의 성격을 바꾼다

지금 POLARIS 는 **편집적 관계 지도**다. 266개 엣지는 사람이 보도를 읽고 그은
판단이고, 그래서 "주장이지 기록이 아니다" 라고 명시한다.

제안된 데이터는 성격이 다르다. 표결 일치도·기부 내역·로비 신고는 **측정값**이다.
둘을 같은 화면에 섞으면 독자가 구분하지 못한다. 그래서:

- 측정된 엣지와 편집된 엣지를 **시각적으로 구분**해야 한다
- 표결 일치도를 관계로 오독하지 않게 해야 한다. Cruz × Hawley 98.6% 는
  "둘이 동맹" 이 아니라 "둘 다 공화당" 이다. 의미 있는 신호는 **당 평균 대비 편차**다
- 기부는 방향이 있는 관계다(A → B). 현재 엣지 모델은 무방향에 가깝다

## ADR 0002 를 다시 열어야 할 수 있다

ADR 0002 는 "데이터는 git 에 두고 DB 를 쓰지 않는다" 로 정하면서, 뒤집을 조건을
적어 뒀다. 그중 하나가 **"아카이브가 50MB 이상"** 이다.

FEC 기부 내역은 선거 주기당 수백만 건이다. 전수를 저장소에 넣는 것은 불가능하고,
집계만 저장하거나 조회 시점에 API 를 부르는 방식이 필요하다. 즉 이 로드맵을
진행하면 ADR 0002 의 재검토가 함께 온다.

## 단계

작은 것부터, 각 단계가 그 자체로 값이 있게.

**1단계 — 조인 기반 만들기**
`congress-legislators` 를 받아 현재 101명에 `icpsr`·`fec`·`bioguide` 를 붙인다.
이것만으로는 화면이 안 바뀌지만 이후 전부가 여기에 얹힌다. 커버리지 56/101 을
데이터로 못 박는다.

**2단계 — 표결 기반 검증 (엣지 추가 아님)**
Voteview 로 기존 엣지를 **감사**한다. "ally 로 표기했는데 표결 일치도가 당 평균보다
낮은" 엣지를 재검토 대상으로 뽑는다. 새 엣지를 대량 생성하지 않는 이유는
39명 × 쌍 조합이 수백 개가 되어 큐레이션한 266개를 묻어버리기 때문이다.

**3단계 — 기부 흐름 (방향 있는 레이어)**
OpenFEC 로 후보별 주요 기부 출처를 집계해 별도 레이어로 얹는다. 기존 관계
그래프와 섞지 않고 토글로 전환한다.

**4단계 — 로비 (LDA 접근 해결 후)**
Senate LDA API 403 을 먼저 해결해야 한다. House 공시는 열려 있으므로 그쪽부터
가능한지 본다.

**5단계 — 스태퍼**
공개 API 가 없어 가장 어렵다. 지출보고서 파싱이나 유료 소스가 필요하다.
앞 단계들이 자리 잡기 전에는 착수하지 않는다.

## 착수 전 결정할 것

- 측정 데이터와 편집 데이터를 **어떻게 구분해 보여줄 것인가**
- 의회 밖 45명을 어떻게 다룰 것인가 (빈 값 표시 / 별도 뷰 / 범위 축소)
- ADR 0002 를 유지할 수 있는 저장 방식이 있는가 (집계만 저장 등)

이 셋에 답이 없으면 1단계까지만 하고 멈추는 것이 낫다.
