Polaris · Technical Overview

Architecture & Data Flow

How a hand-curated relationship graph of U.S. politics stays current: a nightly RSS→LLM pipeline that classifies who is feuding with whom, merged into a rolling 365-day archive (currently ~230 signals) and shipped as static JSON to a force-directed graph in the browser.

System at a glance

The nightly pipeline

01

Fetch

scripts/news-pipeline/fetch.mts

Pulls seven outlet RSS feeds directly, plus per-person Google News RSS queries built from an alias table (trump → "donald trump", "president trump"). Google News results pass a source allowlist of 17 domains and 20 outlet names; articles are then matched back to dataset people by those same aliases. Only articles naming two or more people in the dataset become pair candidates.

02

Classify

scripts/news-pipeline/extract.mts · llm.mts

Pair candidates go to an LLM in batches of ten. For each article it returns the relevant pair, a polarity (ally / feud / neutral), a confidence score, and a two-sentence summary in English and Korean. Runs against NVIDIA NIM's OpenAI-compatible endpoint (nemotron-3-ultra-550b-a55b, temperature 0.2). Without an API key the pipeline degrades to unclassified co-mention signals rather than failing.

03

Merge

scripts/news-pipeline/merge.mts

Each run unions new signals with the existing file by stable id, drops anything older than 365 days, and caps the archive at 1,500 signals. This is what makes the relationship timeline possible — a single run only sees a 30-day window, but the archive accumulates across runs into a year of history.

04

Validate

scripts/news-pipeline/validate.mts

Checks required fields, that stats.total matches the actual array length, and that every referenced person id exists in the dataset — catching drift between the alias table and the politician files before it reaches the app.

05

Commit

.github/workflows/daily-news.yml

The workflow commits src/data/news-signals.json back to the repository at 13:00 UTC daily. There is no runtime backend: the app ships the dataset as a static import, so the whole site is a set of files on a CDN.

Why signals are separate from relationships. The 266 curated edges are the stable structure — who is allied with whom, who mentored whom. News signals are the volatile layer on top. Keeping them apart means a bad classification run degrades freshness, never the underlying graph.

Rendering

ConcernApproach
Layout d3-force via react-force-graph. A custom centering force pulls weakly toward the origin, because link-less nodes otherwise receive only charge repulsion and drift off-screen — inflating the fit bounding box until the real cluster renders tiny in a corner.
Framing Fit runs when the simulation stops, not on a fixed timer, and targets the core 97% of nodes by distance from the centroid. Chasing every last outlier is what shrinks the graph on large monitors.
Stability Nodes are pinned (fx/fy) once the engine settles, so rotation and dragging do not fight the simulation.
3D objects Node meshes are built once and cached by id; selection updates material colour in place. Building them inline meant every click rebuilt all 101 nodes' geometry and canvas textures — a 167 ms frame. Shared unit-sphere geometry, explicit disposal, and labels limited to prominent nodes brought worst-frame to 50 ms and heap from 69 to 40 MB.
Interaction Ctrl-drag rotates in both modes. In 2D it rotates node coordinates about the centroid; in 3D it orbits the camera with unbounded azimuth so the far side is reachable.
Filtering The legend is the filter. Toggling a relationship type hides those edges and dims any node left without a visible tie, so it is obvious what was filtered out rather than silently thinner.
Portraits Wikipedia REST summaries, fetched lazily per person, cached in-memory, with a monogram fallback. No portrait bytes are stored in the repo.
i18n Every label is a { en, ko } pair resolved at render, including LLM-generated summaries — the classifier writes both languages in one pass.
