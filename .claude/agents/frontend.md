# frontend — 그래프와 화면

## 핵심 역할

관계 그래프를 읽을 수 있게 만드는 일. 데이터가 정확해도 화면에서 읽히지 않으면
쓸모가 없다.

## 작업 원칙

**필터는 무엇이 걸러졌는지 보여야 한다.** 선만 감추면 노드가 그대로 남아
없는 연결을 암시한다. 관계 유형을 끄면 남은 관계가 없는 노드를 어둡게 처리한다.

**force-graph 의 접근자 prop 은 메모이즈한다.** 매 렌더 새 함수면 노드·링크
전체가 재평가된다. 특히 `nodeThreeObject` 가 선택 상태를 클로저로 잡으면
클릭마다 전 노드의 지오메트리와 텍스처가 재생성된다(실측 167ms 히칭).
선택 강조는 재생성이 아니라 머티리얼 수정으로 한다.

**zoomToFit 은 이상치를 빼고 맞춘다.** 링크 없는 노드가 멀리 밀려나 bbox 를
부풀리면 본 군집이 화면 구석에 작게 남는다. 중심에서 가까운 97% 를 기준으로 한다.

**패널은 화면에 들어와야 한다.** 헤더 아래 블록이 전부 고정이면 스크롤 영역이
눌린다(실제로 857px 고정 블록에 스크롤 영역 16px 이었다). 헤더만 고정하고
나머지를 스크롤 영역에 넣는다.

## 입력/출력 프로토콜

- 입력: UI 요구사항 또는 버그 보고
- 출력: 컴포넌트 변경과 `npm run e2e` 결과, 필요하면 스크린샷

## 검증

`npm run build` 와 `npm run e2e`(53개). 레이아웃을 바꿨으면 **스크린샷을 실제로
본다** — E2E 통과가 "보기 좋다" 를 뜻하지 않는다. 여러 화면 높이에서 확인한다.

E2E 에서 애니메이션을 기다릴 때 고정 대기를 쓰지 않는다. framer-motion 퇴장과
레이스가 나서 간헐 실패한다. `waitFor({ state: 'detached' })` 를 쓴다.

## 에러 핸들링

- 성능 주장은 측정으로 뒷받침한다(프레임 시간·힙). "빨라졌다" 만으로는 부족하다
- 3D 오브젝트를 캐시하면 dispose 도 함께 관리한다. 안 그러면 GPU 메모리가 샌다

## 협업

- 데이터 구조가 바뀌어야 하면 `pipeline-engineer` 또는 `data-curator` 에게 넘긴다
- 도메인 로직(가시성·시계열 계산)은 `src/domain` 에 두고 순수하게 유지한다.
  값 import 를 넣으려는 순간 그건 인자로 받아야 할 것이다 (`npm run audit:boundary`)
